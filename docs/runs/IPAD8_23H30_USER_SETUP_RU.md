> `task_for_pid-allow` в приложении и helper; установщик вернул 0, открытие
> интерфейса пока не подтверждено. Скрипт подготовки: device/runtimefix/prepare-cocoatop.py.
> UserManagement возвращает пустой список persona. Журнал usermanagerd дополнительно
> сообщает об отсутствующей пользовательской сессии, UserSessionID и PERSONAL PERSONA.

## 2. Как связаны компоненты jailbreak

| Название | Для чего нужно |
|---|---|
| Liter8 | Загружает изменённую систему и ядро; обеспечивает основу этого jailbreak |
| Procursus | Командная строка, APT/dpkg, библиотеки и утилиты в `/var/jb` |
| Sileo | Интерфейс установки DEB-пакетов и зависимостей |
| TrollStore Lite | Установка IPA/TIPA с использованием возможностей уже работающего jailbreak |
| ElleKit | Библиотеки перехвата функций и загрузки твиков |
| Liter8 lhook | Подключает загрузчик твиков к запускаемым процессам; часть именно нашего порта |
| PreferenceLoader | Показывает настройки совместимых твиков в приложении «Настройки» |
| Cephei / libSandy / RocketBootstrap / AltList | Зависимости отдельных твиков; ставятся по необходимости |
| AppSync Unified | Меняет проверки при стандартной установке приложений; для TrollStore Lite не обязателен |
| Filza | Доступ к файловой системе и данным приложений |
| CocoaTop / htop | Просмотр процессов и потребления ресурсов |

TrollStore Lite не превращает этот порт в автономный jailbreak и не восстанавливает SEP. Обычный TrollStore использует другую модель с CoreTrust-уязвимостью и ограниченным набором версий ОС. Для этого устройства нужен именно Lite. [Обычный TrollStore](https://github.com/opa334/TrollStore), [TrollStore Lite от opa334](https://havoc.app/package/trollstorelite).

Здесь пакеты используют архитектуру **`iphoneos-arm64`** и префикс `/var/jb`: это подтвердил `dpkg --print-architecture`. Несмотря на arm64e-процессор, не нужно выбирать DEB `iphoneos-arm64e` для другой среды вроде RootHide. Также нельзя принудительно ставить rootful-пакет `iphoneos-arm` вместо доступного rootless-варианта. Внутренние машинные срезы приложения и архитектура DEB — разные вещи.

## 3. Filza: установить без работающего Files

В TrollStore Lite открой вкладку приложений → **«+» → Install from URL**. Вставь прямую ссылку:

```text
https://tigisoftware.com/download/Filza_NoURLScheme_4.0.2.ipa
```

Подтверди установку, затем открой Filza. Этот путь не требует загружать IPA через Safari или открывать системный выбор файлов. Наличие функции проверено в [исходнике TrollStore](https://github.com/opa334/TrollStore/blob/main/TrollStore/TSAppTableViewController.m), ссылка IPA опубликована [TIGI Software](https://www.tigisoftware.com/default/?p=439).

Проверка после установки: Filza открывается, видит `/var/mobile` и `/var/jb`; обычный файл можно создать, прочитать и удалить в собственной тестовой папке. Это отдельная проверка: совместимость Filza 4.0.2 с нашим 23H30 ещё не подтверждена запуском.

Альтернатива — добавить в Sileo `https://tigisoftware.com/repo/` и установить rootless Filza File Manager 64-bit. В проверенном индексе есть `com.tigisoftware.filza64bit` 4.0.1-4, `iphoneos-arm64`. Выбери один способ установки Filza, чтобы не получить два экземпляра с одним bundle ID.

Filza даёт практический доступ к файлам, но её установка не является исправлением штатного Files, AirDrop или Safari Downloads.

## 4. CocoaTop

Для установки через Lite есть отдельный открытый форк **AlvinHV/CocoaTop-TS**, основанный на D0m0/CocoaTop. В релизе 3.0.0 опубликованы TIPA и DEB для двух схем jailbreak. Это форк, не новый релиз первоначального автора. [Исходники](https://github.com/AlvinHV/CocoaTop-TS), [релиз 3.0.0](https://github.com/AlvinHV/CocoaTop-TS/releases/tag/3.0.0).

В том же меню **Install from URL** можно использовать:

```text
https://github.com/AlvinHV/CocoaTop-TS/releases/download/3.0.0/CocoaTop.tipa
```

Проверка: приложение открывается, показывает процессы и обновляет CPU/RAM. Полнота доступа к чужим процессам зависит от работающих патчей и entitlements; на этом iPad она ещё не проверена. Не используй завершение системных процессов как проверку работоспособности. Уже установлен `htop`: по SSH можно выполнить `/var/jb/usr/bin/htop`.

## 5. ElleKit и настройки твиков: правильный порядок

Сейчас твики не могут загружаться по штатной цепочке Liter8: ElleKit удалён и флаг инъекции выключен. Это не решается одним PreferenceLoader.

1. В Sileo источник `https://ellekit.space/` уже добавлен. Установить из него **ElleKit**, вариант `iphoneos-arm64`.
2. Проверить, что пакет имеет статус `install ok installed` и появились реальные библиотеки. Проверенный индекс предлагает версию 1.2.
3. Проверить связь `/var/jb/usr/lib/TweakLoader.dylib` с загрузчиком ElleKit. Liter8 ожидает этот путь; отсутствие пути — незавершённая интеграция. Не создавать ссылку на произвольную библиотеку по похожему имени.
4. Установить **PreferenceLoader** из существующего Procursus: сейчас доступен 2.2.6-1.
5. Проверить загрузку ElleKit в отдельном тестовом процессе и работу одного минимального твика на этом A12. Только после этого включать общую инъекцию и проверять Preferences/SpringBoard.
6. Добавлять пользовательские твики по одному, проверяя запуск приложения, Settings и сохранение доступа по SSH после каждого изменения.

Команды для проверки, выполняются **в SSH на iPad**:

```sh
dpkg -s ellekit preferenceloader
dpkg -L ellekit
ls -l /var/jb/usr/lib/TweakLoader.dylib
ls -l /var/jb/usr/lib/ellekit
ls -l /var/jb/.lhook_enabled
```

Последняя команда сейчас закономерно показывает отсутствие файла. **Не включай `.lhook_enabled` вслепую одновременно с установкой пачки твиков.** Это переключатель Liter8, а не универсальный шаг из инструкции ElleKit. Его включение действует на новые процессы и само по себе не доказывает исправность инъекции.

Автор ElleKit указывает тестирование iOS 15–27 для arm64 и 15–17 для arm64e. Из этого нельзя вывести гарантированную поддержку A12/arm64e на 26.7.1: проверка нашей цепочки остаётся необходимой. [ElleKit](https://github.com/tealbathingsuit/ellekit), [официальный репозиторий пакетов](https://ellekit.space/).

PreferenceLoader — загрузчик панелей твиков, а не ремонт самого приложения «Настройки». Cephei и остальные библиотеки следует позволить Sileo подтянуть как зависимости нужного твика. Не нужно заранее ставить несколько конкурирующих систем инъекции или все пакеты с названием «Fix». [PreferenceLoader](https://github.com/DHowett/preferenceloader).

## 6. Нужен ли AppSync

На первом этапе — нет. Для установки IPA через TrollStore Lite его добавлять не требуется. AppSync нужен только если позднее потребуется конкретный способ установки через стандартный installd и выяснится, что ему не хватает текущих обходов проверки подписи.

В актуальном описании автора заявлены iOS до 18; проверенного обещания для 26.7.1 там нет. Принудительное снятие ограничения версии в DEB не добавляет совместимость. Если появится необходимость, проверять официальный пакет отдельно, после рабочей инъекции. [AppSync автора](https://github.com/akemin-dayo/AppSync).

## 7. Что конкретно сломано у PosterBoard

Файл `pfwatch` уже установлен и имеет права выполнения. `jbboot.log` многократно доходит до `persona setup done; entering pfwatch`; далее launchd записывает `OS_REASON_EXEC`, namespace 9, code 1, и повторяет запуск примерно через 10 секунд. Собственного `pfwatch.log` нет.

Это отказ исполнения helper до подтверждённой работы его основного цикла, а не просто отсутствие настроенных обоев. Точная причина — подпись, формат/срез Mach-O, политика исполнения или иная проверка загрузки — ещё не выделена. На этом же устройстве вызов `launchctl print` был завершён сигналом 9; это дополнительная причина сначала проверить совместимость привилегированных утилит.

Исправление порта должно дать три результата: `pfwatch` остаётся запущенным; его лог подтверждает успешное исправление конкретного PosterBoard PID; после перезапуска PosterBoard и повторной загрузки результат сохраняется. Повторный `fw finalize` сейчас лишь вновь сообщает о нездоровом watcher и не пересобирает его.

## 8. Files, «На моём iPad», Safari Downloads и AirDrop

Подтверждено:

- `fileproviderd`, `filecoordinationd` и `containermanagerd` работают.
- На диске есть `LocalStorageFileProvider.appex` внутри FileProvider.framework.
- Files оставил crash: `EXC_BREAKPOINT/SIGTRAP`, `_assertionFailure` в `DOCFullDocumentManagerViewController.provideContainerController(...)`.
- Наличие расширения на диске не доказывает его регистрацию и наличие исправного локального домена.

Поэтому сейчас нельзя обещать ремонт созданием `/var/mobile/Documents`, папки Downloads или изменением прав. Отсутствие `Mobile Documents` само по себе также не объясняет отказ: это не универсальная папка «На моём iPad».

Следующий ремонтный шаг — проверить регистрацию локального FileProvider, его домены и создание/доступ к контейнерам под mobile; сопоставить ошибки при открытии Files и сохранении документа. Только после этого выбирать точечное исправление. Не удалять все контейнеры, не выполнять `chmod -R 777 /var/mobile`, не сбрасывать весь LaunchServices-кэш: уже установлены пользовательские приложения, и такой сброс может создать дополнительные проблемы.

Пока Files не исправлен, практический путь — Filza и передача по SSH/SCP. Например, с Mac в существующую временную папку iPad:

```sh
scp -O ./example.txt root@192.168.100.30:/var/mobile/Media/
```

`-O` выбирает старый протокол SCP, поскольку наличие SFTP subsystem в нашей конфигурации Dropbear не подтверждено. Root-копирование создаёт файл от root: для использования приложением mobile можно точечно сменить владельца этого файла, но это не устраняет sandbox/домен FileProvider.

## 9. Karing и отказ добавления VPN

Подтверждён симптом: после разрешения добавить VPN приложение переводит в «Настройки», затем возвращает `permission denied`, не показав ввод кода. Это ещё не проверка успешного запуска туннеля.

Вероятное направление — системное подтверждение/LocalAuthentication в SEP-less, но пока это гипотеза. Нужно отдельно проверить:

- источник и подпись именно установленного Karing;
- entitlement Network Extension и соответствие bundle ID у приложения и karingService;
- регистрацию расширения;
- отказ сохранения конфигурации в nehelper и ответ службы аутентификации в момент нажатия.

Пути Karing.app и karingService.appex подтверждены, но корректность их подписей в этой проверке не установлена. Установка через App Store, TrollStore Lite и стороннюю переподпись может давать разные результаты. [Официальные источники Karing](https://karing.app/en/faq) — App Store и GitHub KaringX.

AppSync и PreferenceLoader не восстанавливают работу SEP и не являются исправлением этой ошибки. Не устанавливать код-пароль/Touch ID как экспериментальный обход: наш порт отключает SEP-зависимые части, и штатная процедура здесь не проверена. Импорт `.mobileconfig` тоже нельзя обещать как решение — он может потребовать того же системного подтверждения.

Если интернет через VPN нужен немедленно, временный вариант — VPN на маршрутизаторе, через который подключён iPad. Он не требует Network Extension на планшете. Обычный HTTP-прокси в Wi-Fi-настройках не равнозначен полному VPN: покрывает лишь поддерживающий его трафик.

## 10. Разумный базовый набор

**Сейчас:** Sileo, TrollStore Lite, Filza одним способом установки, htop (уже есть), CocoaTop-TS после проверки запуска. Этого достаточно для управления приложениями, файлами и процессами.

**После исправления инъекции:** ElleKit + PreferenceLoader, затем зависимости конкретных твиков. Терминал на самом iPad удобен, но не обязателен, пока есть SSH с Mac. Панель управления инъекцией вроде Choicy имеет смысл только после проверки её совместимости; она сама не создаёт отсутствующую загрузочную цепочку.

**По интересам:** настройка интерфейса и жестов, дополнительные действия в приложениях, автоматизация, утилиты разработчика, исследование процессов, приложения/эмуляторы с JIT. Каждый пункт зависит от конкретного приложения и API iPadOS. Наличие root и снятых проверок подписи не гарантирует, что старый твик для iOS 15 поймёт классы и поведение iOS 26.

**Не входят в обещанные возможности этого порта:** восстановление аппаратных функций SEP, рабочий Touch ID/Apple Pay/штатный keychain во всех сценариях, полноценная системная авторизация VPN, работа после обычной загрузки без Liter8, универсальная совместимость всех jailbreak-твиков. Для этих функций нужны отдельные подтверждения, а часть из них несовместима с выбранным SEP-less режимом.

## 11. Повседневное использование и восстановление

Подключение с Mac:

```sh
ssh root@192.168.100.30
```

Пароль SSH не является кодом разблокировки iPad и не связан с Touch ID. Изменять пароль лучше в интерактивной SSH-сессии командой `passwd`, не передавая новый пароль в чат. Учти: нынешние сервисные скрипты Liter8 используют `alpine`; после смены пароля их нужно адаптировать, иначе проверка SSH будет выдавать ошибку.

Для просмотра процессов:

```sh
/var/jb/usr/bin/htop
```

Для проверки пакетов важно читать **Status**, а не только номер версии: удалённый ElleKit был виден в общем `dpkg-query -W` именно из-за оставшихся config-files.

Перед экспериментами сохранить на Mac список установленных пакетов, источники Sileo и ценные пользовательские файлы. Сохранить рабочий каталог Liter8 с контекстом, APTicket, артефактами и точной версией исходников. Сам по себе IPSW не содержит всех результатов настройки нашего порта.

Обычный reboot потребует повторной загрузки через текущую цепочку Liter8/usbliter8. Respring перезапускает интерфейс и обычно не равен полной перезагрузке; при сбое в экспериментальной системе он тоже может закончиться необходимостью DFU. Команду userspace reboot не считать проверенным безопасным аналогом respring для этой сборки.

После физической подготовки pwn DFU команда на Mac:

```sh
cd /Users/ruslan/Documents/ios-jailbreak/Liter8
.build/release/liter8 fw boot --experimental \
  --work-dir .liter8-ipad8-23H30 \
  --irecovery /opt/homebrew/bin/irecovery
```

Она предполагает, что Ramdisk содержит уже собранный **normal** boot-набор. После `get-rd` там будет SSHRD-набор, и сначала потребуется `fw get-boot` с тем же work-dir. Саму CFW повторно записывать для обычного запуска не требуется. `restore-cfw` — стирание/восстановление, не средство перезапуска.

`fw provision` предназначен для SSHRD и не запускается на работающей основной iOS. `fw finalize` работает в основной iOS, но нынешний скрипт ждёт SSH на localhost:2222. Для использования по Wi-Fi можно открыть на Mac отдельный SSH-туннель:

```sh
ssh -N -L 2222:127.0.0.1:22 root@192.168.100.30
```

Порт 2222 должен быть свободен: сначала остановить старый собственный iproxy, если он его занимает. Затем в другом терминале:

```sh
cd /Users/ruslan/Documents/ios-jailbreak/Liter8
.build/release/liter8 fw finalize --check --experimental \
  --work-dir .liter8-ipad8-23H30
```

До исправления pfwatch проверка ожидаемо остаётся INCOMPLETE. Не запускать повторную установку системы из-за этого результата.

## 12. Порядок доведения порта до удобного состояния

1. Сохранить текущую рабочую загрузку и данные.
2. Установить Filza и CocoaTop через URL в Lite, подтвердить их реальный запуск.
3. Исправить исполнение pfwatch и служебного launchctl; проверить watcher и повторную загрузку.
4. Проверить регистрацию/контейнеры FileProvider и восстановить Files, затем отдельно проверить Safari Downloads и AirDrop.
5. Установить ElleKit/PreferenceLoader, проверить инъекцию на A12 и только затем включить её для повседневных твиков.
6. Разобрать конкретный отказ Karing по журналам системного подтверждения и Network Extension.
7. После этих проверок добавлять остальные твики по одному.

Устройство уже загружает изменённую iPadOS. Оставшиеся проблемы относятся к нескольким конкретным подсистемам; установка большого списка «обязательных твиков» их автоматически не устранит.

## 13. FairPlay: можно ли принести зашифрованный IPA и расшифровать

Название защиты — **FairPlay**. IPA — контейнер: он может содержать как зашифрованные App Store-бинарники, так и обычные нешифрованные бинарники разработчика. Даже бесплатное приложение из App Store может быть зашифровано.

| Что есть на входе | Что можно ожидать |
|---|---|
| Нешифрованный IPA разработчика или собственная сборка | Можно пробовать установить через Lite; остаются совместимость ОС, подпись/entitlements и зависимости |
| Уже расшифрованная копия доступного тебе приложения | Шаг расшифровки не требуется; её установка всё равно не гарантирует работу серверов, покупок, keychain и расширений |
| Сырой зашифрованный IPA, скачанный с App Store на другом устройстве/компьютере | Простое копирование и переподпись не расшифруют исполняемый код |
| Установленное приложение, код которого система способна расшифровать и отобразить в память | В принципе применимы инструменты получения расшифрованного образа; работу конкретного инструмента на этом порте нужно проверить |

Инструменты вроде frida-ios-dump используют работающую систему и доступ к приложению/его памяти. Они не являются универсальным офлайн-дешифратором любого IPA. Снятие проверки подписи ядром, установка AppSync или выдача root сами по себе не предоставляют ключи FairPlay. [Исходники frida-ios-dump](https://github.com/AloneMonkey/frida-ios-dump), [проверки encrypted binary в TrollStore](https://github.com/opa334/TrollStore/blob/main/RootHelper/main.m).

**Для данного iPad расшифровка пока не подтверждена.** App Store по сообщению пользователя не загружает приложения, а работа DRM/учётной записи в SEP-less отдельно не проверена. Отказ загрузки в магазине ещё не доказывает невозможность запуска любого ранее установленного приложения; но и рабочий jailbreak не доказывает обратного.

Корректная проверка — взять конкретное бесплатное приложение, доступное твоей учётной записи, установить предусмотренным для него способом, проверить, способен ли этот iPad расшифровать/загрузить код, и только затем проверять инструмент дампа. Если штатная расшифровка кода не работает, перенос сырого IPA и ещё один «decrypt tweak» не решат проблему. Практический путь для собственных приложений — нешифрованная сборка разработчика; для открытых проектов — их официальные IPA/releases.

## 14. Интересные приложения и что из них выбирать

Это подборка проектов с первичными источниками, а не список проверенных на этом iPad программ. Оригинальная поддержка TrollStore до iOS 17 не равна поддержке Lite на iOS 26.

| Приложение | Что интересно | Приоритет для этого iPad |
|---|---|---|
| [Filza](https://www.tigisoftware.com/default/?p=439) | Файлы, plist, архивы, доступ к контейнерам | Первым: полезен независимо от ремонта штатного Files |
| [CocoaTop-TS](https://github.com/AlvinHV/CocoaTop-TS/releases/tag/3.0.0) | Наглядные CPU/RAM и процессы | После Filza; сравнить с уже установленным htop |
| [Apps Manager](https://www.tigisoftware.com/default/?page_id=259) | Резервные копии и восстановление данных приложений | Полезен перед экспериментами; сначала проверить backup/restore на неважном тестовом приложении |
| [UTM](https://docs.getutm.app/installation/ios/) | Эмуляция компьютеров, Linux и другие гостевые ОС | Интересен на iPad; работа JIT и производительность на A12 требуют проверки; виртуализацию с Hypervisor не предполагать |
| [DolphiniOS](https://dolphinios.oatmealdome.me/) | Эмуляция GameCube/Wii | После проверки JIT; A12 не гарантирует полную скорость во всех играх |
| [TrollFools](https://github.com/Lessica/TrollFools) | Встраивание dylib в отдельные приложения | Для последующих экспериментов; автор указывает iOS 14–17, поддержка нашей ОС не подтверждена; не замена системной инъекции Liter8 |
| [Geranium](https://github.com/c22dev/Geranium) | Симуляция геопозиции и управление отдельными системными функциями | Позднее; не начинать с массового отключения служб или очистки: на этом порте уже есть проблемы FileProvider |
| [LiveContainer](https://github.com/LiveContainer/LiveContainer) | Запуск приложений внутри контейнера-хоста | Дополнительный вариант для экспериментов; при наличии Lite обычно не нужен для простой установки IPA, расширения/особые API могут иметь ограничения |

Удобный стартовый набор: **Filza + CocoaTop + Apps Manager**. Для интересных нагрузок затем UTM или DolphiniOS. TrollFools и системные функции Geranium лучше оставить до стабилизации FileProvider, служебных утилит и инъекции.
